## 一、背景与目标

当前项目已完成「表单记账 + 流水列表」的最小闭环，但页面样式朴素，后端仅支持新增与查询，无法修改、删除、筛选。

本次改造目标：

1. **页面美化**：暖色招财主题，README 级别的视觉升级，保留现有功能不回归。
2. **招财猫助手**：可动、可点击，用户用一句话告诉它今日流水，由它解析并帮助记账，也能播报今日收支。
3. **解压小木鱼**：点击敲击、有动画音效与功德计数，纯前端彩蛋。
4. **后端能力补齐**：删除记录、修改记录、多条件查询（关键词 / 类型 / 日期 / 分页）、今日汇总。

### 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 招财猫语义解析 | **规则为主 + 预留大模型开关**：本地关键词/正则解析，后端预留 `/api/chat` 骨架，配置 Key 后可切换 |
| 修改 / 删除交互 | **点击行展开右侧滑出面板（抽屉）**，面板内编辑与删除 |
| 本轮动作 | 先出计划，暂不实现 |

## 四、招财猫助手设计（核心）

### 4.1 造型与动画实现

- 用**内联 SVG** 手绘招财猫（身体、耳朵、胡须、围巾、举起的前爪、金币），不依赖外部图片，便于分部位做动画。
- 状态机：

| 状态 | 表现 |
| --- | --- |
| `idle` | 整体上下轻浮动 + 缓慢摇尾 + 定时眨眼 |
| `hover` | 抬起前爪招手 |
| `click` | 弹跳一下 → 展开对话面板 |
| `thinking` | 爪托下巴 + 气泡「喵～让我算算…」 |
| `happy` | 入账成功：撒金币粒子 + 笑脸气泡 |

### 4.2 交互流程

1. 点击招财猫 → 展开对话气泡（含快捷话术 chips：`午饭 30`、`打车 15 元`、`工资 8000`、`今天花了多少`）。
2. 用户输入文本 → 本地 `parseRecord(text)` 解析为结构化账目：
   - **分类映射**：吃饭/午饭/火锅 → 餐饮；打车/地铁/公交 → 交通；买/购物/衣服 → 购物；电影/游戏 → 娱乐；工资/奖金/报销/收到 → 收入；其余 → 其他。
   - **时间**：默认当前时间，支持「昨天 / 前天」。
   - **金额**：兼容 `30`、`30元`、`30块`、`30.5`。
3. 猫回一张**确认卡**（类型、金额、分类、时间、备注）：
   - 「确认记账」→ 调用 `POST /api/records`，成功后刷新列表与概览卡；
   - 「改一下」→ 把内容回填左侧表单。
4. **问句意图**（今天花了多少 / 今天流水）→ 调用 `GET /api/records/summary`，猫用气泡播报：今日支出 ¥xx、收入 ¥xx、共 n 笔。
5. 解析失败 → 猫反问「没听明白喵，你是想说『午饭 30』吗？」，并提供一键回填表单，**不静默失败**。
6. 上下文记忆：会话内记住上一笔分类，支持「再来一笔 20」这类追问（仅内存，不持久化）。

### 4.3 规则为主 + 大模型开关

- 前端设 `PARSE_MODE = "rule" | "llm"`：
  - `rule`：本地解析（默认，离线可用、零成本）；
  - `llm`：调用后端 `POST /api/chat`。
- 后端预留接口骨架：

```json
// POST /api/chat   请求
{ "text": "午饭花了30" }

// 响应（未配置 Key 时的占位）
{ "code": 200, "mode": "rule", "message": "未启用大模型，请使用规则解析", "data": null }
```

- 启用方式：配置环境变量 `LLM_API_KEY` 后，后端改为真实调用并按统一结构返回 `{type, amount, category, remark, recordTime}`；前端异常时自动回落规则解析。

## 五、小木鱼设计（解压彩蛋）

- SVG 木鱼 + 木槌；点击时木槌下压、木鱼缩放回弹 + 金色涟漪扩散。
- 音效用 **WebAudio 现场合成**（短促「笃」声，无需音频文件，`file://` 打开也能响）。
- 飘字「功德 +1」随机角度上浮消散，连点可叠加。
- 计数存 `localStorage`，展示「今日功德 N」，右上角提供小字「清零」。
- 位置：桌面并入招财猫宠物区，移动端固定左下，不遮挡主内容。
- 浏览器自动播放策略：首次点击后再初始化 `AudioContext`。

## 六、后端接口改造（main.py）

数据库表结构不需要变更。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/records` | 扩展参数：`pageNum`、`pageSize`、`type`、`keyword`（分类/备注模糊）、`startDate`、`endDate`；返回 `total` 与 `list` |
| GET | `/api/records/summary` | 今日汇总（可用 `?date=YYYY-MM-DD` 指定日期）：收入合计、支出合计、结余、笔数；可带 `recent` 最近 3 笔 |
| GET | `/api/records/{id}` | 查询单条，供抽屉回显；不存在返回 404 |
| PUT | `/api/records/{id}` | 全量更新 type / amount / category / remark / recordTime，复用现有校验 |
| DELETE | `/api/records/{id}` | 删除记录；不存在返回 404 |
| POST | `/api/chat` | 预留：自然语言解析（当前返回 `mode:"rule"` 占位） |

### 统一响应约定

- 成功：`{ "code": 200, "message": "...", "data": ... }`
- 参数非法：HTTP 400 + 中文提示（金额 ≤ 0、分类为空、时间格式错误等）
- 资源不存在：HTTP 404
- 时间格式保持 `yyyy-MM-dd HH:mm:ss`

### 校验规则（沿用并复用）

- `type` ∈ {1, 2}；`amount > 0`；`category` 非空；`recordTime` 必须匹配格式。
- 关键词查询对 `category`、`remark` 做 `LIKE %kw%`，需注意参数化查询防注入。

## 九、风险与兜底

| 风险 | 应对 |
| --- | --- |
| 自然语言有歧义 | 一律走「确认卡」再入库；解析失败回填表单，不静默失败 |
| 分页后统计不准 | 今日数据必须走 summary 接口，不能只统计当前页 |
| 音效被自动播放策略拦截 | 首次用户点击后再初始化 `AudioContext` |
| 大模型不可用 / 无 Key | `PARSE_MODE=llm` 时异常自动回落规则解析 |
| 修改后数据错乱 | PUT 全量校验 + 成功后重拉当前页与 summary |
| 删除误操作 | 抽屉内二次确认，确认按钮使用危险色并展示记录摘要 |
