> 更新时间：2026-11-16 ｜ 版本：v2.0 ｜ 演进阶段：**优化迭代**（v1.0 已上线，本轮做能力扩展）

## 1. 使用场景

| 项 | 内容 |
| --- | --- |
| 解决什么问题 | 把「每天记账、月底看账」这件每天重复的事自动化：固定收支自动入账、每天自动出小结、每天自动做消费复盘 |
| 给谁用 | 个人用户（单机自用，Windows + 本地 MySQL） |
| 触发频率 | 3 条定时任务（每日）+ 随时手动触发 + 招财猫对话随时记账 |
| 运行方式 | 后端常驻（APScheduler 随 FastAPI 启停），前端 `file://` 或浏览器打开 |

### 本轮自动化覆盖的「每日重复工作」

| 重复工作 | 自动化方式 | 触发时间 |
| --- | --- | --- |
| 记固定收支（房租/订阅/工资） | 周期账单规则自动入账 | 每天 00:05 |
| 看今天花了多少 | 招财猫对话 + 概览卡实时统计 | 随时 / 实时 |
| 每日收支小结 | 自动生成日终汇总推送到消息中心 | 每天 23:00 |
| 每日消费复盘 | 结构化统计 + 点评文案写入消息中心 | 每天 23:10 |
| 预算超支 | 汇总时检测并生成 danger 级预警 | 每天 23:00 |

## 3. 数据源清单

### 3.1 数据库（本地 MySQL `account_db`）

| 表 | 用途 | 关键字段 | 写入方（唯一写入方） |
| --- | --- | --- | --- |
| `account_record` | 记账流水 | `type`(1收/2支)、`amount`、`category`、`remark`、`record_time`、`account_id` | 应用（人工录入 + 招财猫 + 周期账单自动入账） |
| `account_book` | 账本（多账户） | `name`、`book_type`、`init_balance`、`icon`、`is_default` | 应用 |
| `recurring_rule` | 周期账单规则 | `cycle_type`(daily/weekly/monthly)、`cycle_value`、`start_date`、`end_date`、`auto_post` | 应用 |
| `recurring_run` | 周期账单执行记录（幂等判重） | `rule_id` + `period_key` 唯一键 | 调度器 |
| `budget_rule` | 分类预算 | `category` + `period` 唯一键 | 应用 |
| `daily_report` | 日报 / 消息中心 | `report_date` + `report_type` 唯一键 | 调度器 + 手动触发 |
| `task_run_log` | 自动任务执行日志（失败留痕） | `task_name` + `run_date` 唯一键 | 调度器 |
| `checkin_log` | 记账打卡 | `check_date` 唯一键、`record_cnt` | 应用（新增流水时累加） |

> 字段以实际建表为准，见 `db.py` 的 `SCHEMA_SQL`。`account_record.account_id` 由 v1.0 增量迁移新增，老数据统一归属默认账本（id=1），迁移可重复执行不丢数据。

### 3.2 外部服务（可选）

| 服务 | 用途 | 鉴权 | 同步方式与频率 |
| --- | --- | --- | --- |
| 大模型 API（OpenAI 兼容协议） | 招财猫智能解析、多笔拆解、消费点评 | `Authorization: Bearer {LLM_API_KEY}`，环境变量注入 | 按需调用，无 Key 时自动回落规则 |
| 本地 MySQL | 全部业务数据 | 用户名密码，`DB_*` 环境变量可覆盖 | 实时 |

## 4. 自动化规则

| 规则 | 触发条件 | 执行逻辑 | 幂等键 | 异常兜底 |
| --- | --- | --- | --- | --- |
| 周期账单自动入账 | 每天 00:05（APScheduler CronTrigger，Asia/Shanghai） | 扫描 `recurring_rule` → 判断是否命中周期 → 生成 `account_record` → 写 `recurring_run` | `(rule_id, period_key)` 唯一键；已处理则跳过 | 异常写 `task_run_log(status=failed)`；消息中心留痕；`auto_post=0` 时只生成待确认提醒不直接入账 |
| 日终汇总播报 | 每天 23:00 | 汇总当日收支/分类/环比/预算进度 → 生成小结文案 → 写 `daily_report(type=summary)` → 预算超支另写 `type=warning`(danger) | `(report_date, report_type)` 唯一键，同日覆盖 | 大模型失败回落规则文案；任务异常写日志 |
| 每日消费复盘 | 每天 23:10 | 结构化统计 → 大模型点评（失败回落规则复盘文案）→ 写 `daily_report(type=review)` | 同上 | 同上 |
| 预算超支预警 | 随日终汇总触发 | 分类用量 > 预算 → 生成 danger 级预警 | 同上 | — |
| 消息未读数刷新 | 前端每 60 秒 | 拉取未读日报数 → 铃铛角标 | — | 网络失败静默重试下一轮 |

### 手动触发入口（便于调试与即时使用）

| 入口 | 接口 |
| --- | --- |
| 立即检查并执行周期账单 | `POST /api/recurring/run` |
| 立即执行单条规则 | `POST /api/recurring/{id}/run` |
| 立即生成日终汇总 | `POST /api/automation/run-summary` |
| 立即生成消费复盘 | `POST /api/automation/run-review` |
| 生成月度账单解读 | `POST /api/chat` `{text:"分析一下本月账单"}` |

### 可靠性设计

- **幂等**：所有自动写操作都有唯一判重键，重复触发不产生副作用
- **重试**：大模型调用最多重试 2 次，指数退避 1s → 2s；4xx 属确定性错误不重试
- **降级**：大模型不可用 → 后端规则 → 前端本地规则，三级回落，功能永不中断
- **失败通知**：任务失败写 `task_run_log`，消息中心可见，不静默中断
- **时区**：显式 `Asia/Shanghai`，不依赖服务器默认时区
- **超时**：大模型请求 30 秒超时
- **人工确认**：周期账单可设 `auto_post=0` 只提醒不入账；删除记录保留抽屉二次确认

## 5. 权限说明

- 本项目为单机个人应用，无多用户权限体系
- **密钥存放位置**（只写位置，不写密钥本身）：
  - 大模型 Key：环境变量 `LLM_API_KEY`（可选，不配则走规则模式）
  - 大模型地址/模型：`LLM_BASE_URL`、`LLM_MODEL`（可选）
  - 数据库账号密码：环境变量 `DB_USER` / `DB_PASSWORD` / `DB_HOST` / `DB_PORT` / `DB_NAME`（可选，默认值在 `db.py` 的 `DB_CONFIG`）
- **密钥绝不入库、不进提示词、不进前端代码**
- 前端页面不存储任何凭据
